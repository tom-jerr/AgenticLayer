摘　要

智能体的一次用户输入会触发多次推理、工具调用、子任务和上下文变换。仅缩短单次生成无法消除整轮阻塞。AgenticLayer 将框架已确认的依赖、逻辑上下文版本与引擎物理状态交给同一个控制层：先判断动作是否合法、资源是否允许，再决定应否并行、何时准备以及哪些状态可以释放。

在固定 CUDA Graph 的真实工具与 GPU 受控试验中，合法并行 + 付费前瞻使整轮 P95 下降 51.44%，独立复验下降 41.53%。而在独立的 FreeInference 留出回放中，联合策略比强组合只快 1.56%，区间跨 0，且没有触发可选准备或迁移。证据支持按依赖和等待窗口启用机制，不支持默认全开。

在缓存工程方向，drop / repos 键旋转复用让 FreeInference 16 周真实尺度回放的重预填 token 相对原生窗口滑落与「丢弃后冷启动」分别减少 2.7× 与 3.5×，TTFT P95 低 1.8× 与 1.4×；DSH 消息级丢弃闭环与 Triton 旋转核已接通，控制路径优化（RPC 39×）使全量回放总墙钟再降 21.5%。

关键词：智能体服务；活跃轮次；KV 缓存；上下文版本；联合调度

01动机与背景

单轮聊天近似一次模型调用；智能体轮次则交替经过 GPU 推理、CPU / I/O 工具、子智能体汇合和再推理。工具等待可能提供后台窗口，但等待不是空闲的同义词：另一个分支可能正在解码，或者在等待同一条恢复链路。上下文被改写后，即使后缀文本相同，其旧状态也可能已不合法。[1]

因此，优化对象是活跃轮次：从用户输入就绪到最终回复完成，包含排队、模型调用、工具和必要变换，不含之前的用户空闲。论文的问题不是每个模块能否单独提速，而是：在依赖动态揭示、版本可能变化、资源固定的前提下，统一选择动作是否比各模块独立仲裁更有用？

03对比与实验设置

相关工作提供不同能力：KVTether 把框架事件映射为缓存生命周期，SmoothAgent 提前准备上下文，MORI 聚焦 GPU / 主机放置，TOPAS 用工作流结构与缓存驻留共同指导准入。这里比较的是同一实现中这些决策是否值得联合，不把文献中的不同硬件、负载或指标混入测速。[1]

证据分层。 真实工具 + GPU 的受控任务用于机制归因；真实 FreeInference 留出轨迹按匿名块、因果和等待屏障投影，用于检查机制是否触发及观察覆盖率，不执行原始工具，不测原始任务正确性。主指标是整轮 P95；配对差的区间跨 0 不作明确增益，行为或数值门禁未通过不作同质量提速结论。

04主实验：联合有效，但有覆盖边界

4.1　真实工具与 GPU：并行 × 付费前瞻

在同一任务上交叉切换串行 / 合法并行与同步 / 提前准备，计入摘要生成、预填充与未完成回退。原试验和独立复验都通过全部 10 对工作量门禁；两项全开在两次四臂对照中均为最短的 P95。

并行让工具更快返回，也缩短了准备窗口：在串行 + 前瞻臂，两次都 10/10 使用候选；在并行 + 前瞻臂，则为 7/10 和 5/10。两次交互差分别为 +84 ms（[−827, +832] ms）和 +346 ms（[−544, +922] ms），不足以确认额外协同或抵消，不能相乘单项加速比。

4.2　FreeInference 留出回放：没有可归因的联合提速

首批 12 轮、43 请求、29 个屏障的固定图参考结果中，原生 Radix / HiCache / strong / joint 的 P95 为 32.508 / 32.564 / 33.583 / 36.073 s。受控臂主要只选 admit；该批次不能验证多个可选动作竞争的好处。随后排除首批全部根会话，在无重叠的 12 个会话上复验：13 轮、135 GPU 请求、119 个屏障，60% Full / Mamba 配额和 4 GB host。

07案例研究：一次命中、一次回退、一次被拒绝的释放

7.1　候选完成才切换，不把请求发出算作命中

在第二次四臂复验的并行 + 前瞻臂中，第 2 对的候选在切换前已就绪，第 1 对则仍在执行。两例都是相同配置下的真实回执。下图只标付费摘要、开始准备和检查点；灰色虚线表示候选从申请到检查的观察窗口，不把它误画成实际 GPU 执行跨度。

7.2　父分支改写，子分支仍持有旧前缀

  1. 父分支由 A ∥ B 改写为 A′ ∥ B；父的新请求不再命中旧前缀。子分支仍合法引用旧版本，4K 前缀命中 4096 token。
  2. 租约存在时原生回收被拒绝。子分支释放后，修复路径允许直接弃置无主且未备份的叶节点，不为回收强制发起一次 D2H。
  3. 4K 第 0 对中，保护解除后约 10.0 ms 收到回收确认，物理 HBM 约减少 177.1 MiB；保留臂观测窗口为 600 ms，无释放。两组子分支输出相同。这是一次原始事件轨迹，不是均值。[6]

08缓存工程：drop / repos 键旋转复用与真实尺度消融

8.1　动机与背景

上下文工程（裁剪 / 摘要）改写轨迹前缀后，保留后缀必须整体重预填：AKV 实测 trim 的成本反而达到全量的 1.85×。FreeInference 16 周全量画像与这一结论一致：12,002 个会话、1,222,199 次递归请求，上下文 P50 达 118,080 token（32K 窗口的 3.6 倍），前缀改写事件 53,798 次（mutation 45,099 + switch 8,699）。任何文本级裁剪都要把改写点之后全部重算；按中位前缀折算约 6.2×10⁹ token 的重复预填充。

三条路径因此可消融：full（不丢弃，窗口滑落时整窗冷预填）、trim（丢弃中段后冷启动，今日压缩路径）、cache-eng（丢弃同一段后按 RoPE 键旋转复用，只预填增量）。比较的正是 AKV 的核心矛盾：裁剪省了上下文，却把 re-prefill 买回来。

09讨论与结论

证据支持的是条件式跨层优化：了解依赖才能利用并行，了解版本才能安全复用和回收，了解实际等待才能判断准备是否值得。把三者放到同一控制点的价值，不等同于每个负载都有多个候选需要联合排序。

可以优先启用
已确认独立的工具与子任务；稳定长等待内的付费前瞻；确认过期且无租约、无在途依赖的回收。
需要条件门禁
CPU 争用明显时限额，轻 I/O 保持合法即发；短窗口只做可按时得到完整 ACK 的恢复，不抢跑赶不上切换点的准备。
暂不作为默认
匿名回放、漂移未校准或长窗口数值门禁未通过时，不把联合全开当作默认；保留 strong。

局限性。 单卡、固定模型、留出会话数有限，nearest-rank P95 在 12–13 轮时就是最慢轮次。同一热分段下物理迁移 9/9 数值一致，但相对整段冷参考 0/9 达到原容差，不能声称跨分段等价。受控摘要也不证明一般摘要质量。
