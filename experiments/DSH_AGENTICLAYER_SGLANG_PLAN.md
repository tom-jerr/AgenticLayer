# Qwen3.5-9B NVFP4：DSH × AgenticLayer × SGLang 实验

## Context
以 `main.pdf` 第三至五章为实验合同。先确认本机原生 baseline，再用 `/root/autodl-tmp` 的 FreeInference 轨迹测试；实现 DeepSeek Harness (DSH) → AgenticLayer → SGLang 的三层系统，以及工具并行、子智能体委派、工具结果缓存、批会话、生命周期与联合控制。统一 `page_size=1`，使用 Triton；联合控制的增量以论文表 5-1 的强组合而非弱串行基线衡量。

## 已确认的输入
- 当前工程只有 `main.pdf`。本机 RTX 5090（32607 MiB、驱动 580.105.08）；默认 Python 的 Torch 2.7 cu128 / Triton 3.3 不代表 SGLang 已可启动。`/root/.cache/huggingface/hub/models--AxionML--Qwen3.5-9B-NVFP4` 已有本地快照；邻居 `/root/AgentArch` 有 SGLang 源码和已有实验环境，不能把其 4B AWQ 合同或 AgentX fixture 当成本项目基线。
- `/root/autodl-tmp/README.md` 确认 FreeInference 16 周、12002 会话、1186582 模型请求、1213347 工具调用。`release/<week>/traces/<day>.jsonl.zst` 每行是一个会话，包含嵌套 subagent；同周 16-token block ID 可组织合成前缀，跨周不共享。无原始文本、真实工具结果或可验证读写依赖；不能重跑匿名工具、从时间重叠推断可并行、把轨迹回放说成任务质量测试。
- 确认两个主基准角色：未挂插件的原生按需；表 5-1 强组合（与联合策略共享合法性、老化、容量、准备保护，唯独没有跨动作排序）。论文已有阶段性验证没有可复核量化日志，不继承为结果。


## Approach

### 1. 冻结原生 baseline（进入机制开发前）

- 在本仓建立 `agentic_layer/`（Python 中间层、SGLang 插件、评测）、`dsh-agentic/`（DSH 插件与受控 runner）、`experiments/`（固定矩阵/样本协议）；依赖隔离在项目自己的环境，不编辑 `/root/AgentArch`、模型目录或数据目录。大产物放 `/root/autodl-tmp/agentic-layer-runs/<run_id>`，不写 `release/` 或 `viewer/`。浏览器或远端模型不进入测量；所有服务监听 loopback。
- 唯一权重为 `AxionML/Qwen3.5-9B-NVFP4` 本地 snapshot `97aef92393f126bf649f310cd40861be8dad3279`。`hf_quant_config.json` 为 ModelOpt NVFP4 权重，`kv_cache_quant_algo=null`；显式固定 BF16 推理/KV，不将 NVFP4 权重量化等同 KV 量化。`config.json` 为 32 层，其中 8 层 full attention，24 层 linear attention；复用/恢复必须同时考虑 KV 与 linear recurrent/conv state。用原模型的真实 tokenizer/chat template，统一关闭 thinking、greedy、TP=1、无 speculative decoding、Triton full-attention、`page_size=1`。上下文 32768、生成任务上限 512、回放解码上限 128、并发上限 8，先对 32768 token 做无 OOM 门禁。记录实际 Mamba 状态池、KV 容量、驱动、库版本、依赖锁、GPU 时钟/功耗、并发预算和加载到的量化 GEMM；不替换为 BF16 权重、其他模型或非 Triton attention。Driver 580.105.08 报 CUDA 13.0。
- `native-radix` = DSH 同一个受控套件 + 无 AgenticLayer、无 HiCache 的原生 SGLang（开启原生 radix/LRU）；`native-hicache` 仅增加原生实例私有 DRAM HiCache，用作按需恢复参照。原生 DSH 默认行为只跑一次实闭环演示，机制表中的 `serial` 明确指同一调用集合的受控串行，不误标 DSH 默认。`reference-cold` 仅做逐 token 数值对照：禁 radix、禁 HiCache，复用相同后端、量化、模板和采样；混合状态起点为零。用原生 `/generate` 做固定 token IDs 的 cold/warm、logprob 和 cache-hit smoke；用 `/v1/chat/completions` 验证工具解析与 DSH 连通。邻仓 `baseline-launch.log` 停在缺 NumPy，不能用作任何成功证据。
- 全部语义组固定工具、结果、边界、任务、外生到达、硬件上限与采样；原生组不加载插件，所有扩展组使用同一插件变体，以一个配置选择策略。`prepare` 校验模型及 tokenizer 实文件 SHA-256、源 revision 与依赖，生成 `manifest.json`；`baseline` 先产 `baseline.json`、原始请求/响应/时间线和锁的 hash，后续命令拒绝缺失或不匹配的 baseline。HBM/DRAM 压力实验中的不同预算各有匹配基线。模型缺档、NVFP4/Triton 初始化失败、HiCache 不可用时该基准为失败，不以临时替换配置产表。
- 先实现 `experiments/bootstrap.sh`、CLI `prepare/baseline` 和第 4 步的 DSH 原生 route/SDK smoke，此时不加载控制 hook。baseline OK 后先跑第 2 步的原生数据 smoke。随后依次接中间层、DSH hooks、后端插件、策略矩阵。模型、源码或依赖改变必须新建 run，不沿用旧的性能基线。
- 运行目录先设 `export RUN=/root/autodl-tmp/agentic-layer-runs/5090-nvfp4-01`；在 `$RUN/env/python` 建 Python 3.12 venv，`UV_CACHE_DIR=$RUN/cache/uv`、`TMPDIR=$RUN/tmp`、`TRITON_CACHE_DIR=$RUN/cache/triton`、FlashInfer/CUDA JIT 缓存也写 `$RUN`。根 overlay 仅约 6.8 GB 空闲，SSD 实测约 42 GB，不在根目录重复解包 CUDA wheels。SGLang 固定 `703e763d5f3af75ea3587275d79155c28d3c5d4f`（邻仓已有完整 tar/source；复制到 `$RUN/src/sglang`，核对 tar SHA-256 和目录内源码 hash，取不到则从 GitHub 此精确 SHA 下载并固定 hash）。用 `SGLANG_BUILD_RUST_EXTS=none SETUPTOOLS_SCM_PRETEND_VERSION=0.5.23.dev0+g703e763d UV_HTTP_TIMEOUT=120 UV_CONCURRENT_DOWNLOADS=2 uv pip install --python "$RUN/env/python/bin/python" "$RUN/src/sglang/python"`，选该源码声明的 Torch 2.14.1、FlashInfer cu13 0.7.4；构建仅使用已选 Python TreeCore，不修改邻仓。网络慢则对同一索引位置下载 wheel 到 `$RUN/wheels`（可断点续传，按索引 SHA-256 校验后本地装相同制品）；如果宿主驱动拒绝该 CUDA build 或未能下载，留下原始安装/启动错误，不跳到另一版产性能结论。不要用现有 Torch 2.7 环境覆盖。
- 启动命令：`CUDA_VISIBLE_DEVICES=0 HF_HUB_OFFLINE=1 SGLANG_PLUGINS=__no_plugins__ SGLANG_CACHE_DIR="$RUN/cache/sglang" SGLANG_UNIFIED_RADIX_TREE_CORE_BACKEND=python SGLANG_DECODE_STATE_FREE_RADIX=0 SGLANG_OPT_MAMBA_HOST_ONLY_CHECKPOINT=0 "$RUN/env/python/bin/python" -m sglang.launch_server --model-path "$MODEL" --served-model-name qwen35-9b-nvfp4 --host 127.0.0.1 --port 30080 --tp-size 1 --quantization modelopt_fp4 --fp4-gemm-backend flashinfer_cutlass --dtype bfloat16 --kv-cache-dtype bf16 --attention-backend triton --linear-attn-backend triton --linear-attn-prefill-backend triton --linear-attn-decode-backend triton --page-size 1 --mamba-radix-cache-strategy no_buffer --disable-overlap-schedule --mamba-ssm-dtype float32 --hybrid-cache-checkpoints-level 2 --context-length 32768 --chunked-prefill-size 2048 --mem-fraction-static 0.80 --max-running-requests 8 --radix-eviction-policy lru --tool-call-parser qwen3_coder --reasoning-parser qwen3 --enable-metrics --cuda-graph-backend-decode disabled --cuda-graph-backend-prefill disabled`。`$MODEL` 是唯一快照绝对路径。`native-hicache` 加 `--enable-hierarchical-cache --hicache-size 16 --hicache-write-policy write_back --hicache-mem-layout page_first --hicache-io-backend kernel`，无 L3；`reference-cold` 加 `--disable-radix-cache`，无 HiCache。ReplaySSM、Mamba INT8、unified-memory 保持禁用。请求显式 `chat_template_kwargs={"enable_thinking":false},temperature=0`，报表注明 Python TreeCore、关闭 overlap/graph。不要将 `SGLANG_PLUGINS` 设为空串：空串加载所有发现的插件。
  - 现场无 `nvcc`；执行阶段将 NVIDIA CUDA Toolkit 13.0.2 放 SSD 独立目录供 JIT，设置 `CUDA_HOME`、`PATH` 并以 `nvcc --version` 和实际 `sm_120` Triton / FlashInfer 初始化验证。不要更新宿主 driver，也不把系统 toolkit 的运行时混入 Torch 依赖。失败保存安装/驱动报错，不计入性能表。

### 2. 数据集：先画像，再回放，再单独测闭环

- `agentic_layer/trace.py` 用 `zstandard.ZstdDecompressor().stream_reader` 逐行读所有 `release/*/traces/*.jsonl.zst`（不是把 Parquet 全部读进内存）。递归展开 `requests[*].tool_calls[*].subagent`，稳定身份为 `(week, session_id, child_call_path, step)`；根用户轮次按 `turn_index` 分组。校验并输出根会话/请求/工具数量、时间异常、嵌套深度、上下文长度、LCP、mutation (`append`, `mutation`, `switch` 及 `cause`)、多调用和子分支覆盖；空 `block_ids`、负延迟、缺失工具链接或不合格超长轮次记录逐原因；不作为空样本、也不暗中截断。首周实际扫出 106 根会话、10738 个递归请求、747 个多调用请求、19 个嵌套子会话；完整块长度 P50/P95=91056/166592，需压缩投影。第 1–4 周仅校准；最后 4 周留作评测，样本哈希及排除数入 manifest。
- 回放映射固定：基于实际 tokenizer 枚举普通 token ID（排除全体 special/control IDs，取最小 16384 个；不足时拒绝）；每个 16-token 块用 SHA-256(`week`, 父链摘要, block_id) 映射为其中两个 ID，按链级维持一致，扫描选中语料并检测同父 2-ID 碰撞，按稳定排序加 salt 重映射直到唯一；同一匿名链严格保留以块计的共享前缀度，禁把不同周当同一命名空间。报告 8×投影、忽略原轨迹最后不足一块的尾部、匿名 LCP 与实际 engine 命中（不承诺 token 级原始命中）；筛掉投影后 prompt+128 >32768 的完整轮次；每请求生成 `max(1,min(provider_tokens.completion,128))` token，缺值按 1 并计数，`ignore_eos=true`，不使用生成内容串接下一条投影 prompt。不可把映射 ID 解释为原文本。
- 选择完整根轮次、单周内去重 `(week,session_id,turn_index)`，同会话从首个选中轮次开始注入前缀长度；后续仅使用选中轮次的真实前驱关系，不把省略的历史映射为已驻留 KV。按互斥优先级 `子会话 > mutation/ switch > 多调用 > 普通` 分层；每层按 `SHA256("agentic-kv-v1"+week+session_id+turn_index)` 排序取 16 个 smoke / 64 个主测，总量不足时取实际量、报告缺额与选择率，不跨层补齐。边界指标用分层报告及明确标注的等权混合总体；再由全量画像给出代表性范围，不把过采样集当全体生产分布。
- 回放用记录给出根轮次外生到达与因果关系；组内相邻根轮次间隔裁剪至 `[0,1000]ms`，每组最大 8 条不同根会话。同一会话下一轮不早于上一轮实际结束和下一条外生到达；后继 engine 请求只在实际前驱提交后发出，禁止用 `start_ms` 发后继。`latency_ms` 是到后续请求的观察间隔，不是逐工具服务时间；批使用保守屏障 `min(2000,max(finite_nonnegative_latency_ms))` ms，缺值用 0 并计数。多子会话按 `call_index` 依次递归回放；取其总耗时与屏障的 `max`，不重复相加。连接不充分沿记录顺序运行。模型实际跑 GPU，工具侧只回放时间与屏障，不执行匿名命令、不从匿名多工具推断并行性；分支并行只在有独立性证据的 E1/E2/E5 测。轨迹 mutation 代表观察到的 prompt 替换，不声称知道原始语义/摘要/工具结果。
- 真实闭环单列：在自建、固定内容的临时工作区运行 DSH + 本地模型；可验证的工具为快照文件读、校验、合并、固定子任务与单次写入，不执行轨迹提取的内容，也不访问网络。固定绝对任务结果（例如读两个独立文件合计为 42、验证唯一 commit marker）和输入快照。工具结果缓存开关使用同一批重复实任务（冷、热、数据版本改变、权限改变），记录实际执行次数与结果，不能从脱敏的 `<path>` 参数合并推估命中。记录开放闭环中自然生成的工具序列变化、pass/fail，不与保持相同调用集合的系统消融合并。

### 3. 中间层协议及上下文状态

- 新建 `agentic_layer/protocol.py` 和 FastAPI ASGI `agentic_layer/server.py`。DSH 拥有消息/工具日志，AgenticLayer 拥有目录、队列、策略，SGLang 独占物理槽位、radix、allocator 与 CUDA event。Loopback Bearer token 绑定本地可信 DSH；引擎有每次启动 UUID `epoch`。`POST /v1/chat/completions` 保留 OpenAI payload/SSE，模型隐藏 header 为 `X-Agentic-Session/Branch/Version/Request`（Request 对应唯一 `rid`）；`POST /agentic/v1/events` 的 JSON 为 `{run_id,session_id,branch_id,seq,event_id,expected_version,kind,payload}`，成功回 `{event_id,version_id,status,permit}`，`permit` 非空时包含 `{action_id,version_id,expires_mono_ns}`，必须在 dispatch 之前核对；`ready` 在可取消请求内等待 grant，其他事件 ACK 后立即返回。`POST /agentic/v1/batch` 接 `{"items":[{"session_id", "branch_id", "version_id", "rid", "input_ids", "sampling_params"}]}`，每条结果保留 `rid,status,result/error`，送原生 batch。首次 session append 允许 `expected_version=null,seq=1`；后续每 branch `seq` 单调，与 `event_id` 全量内容做幂等校验，同 ID 异内容或 seq/version 不符 `409`，未知句柄 `404`，格式 `422`；已完成 cancel 返回既有终态。fork payload 包 `parent_branch_id,parent_version,child_branch_id`，不得跨隔离域。所有状态/缓存命令、资源日志记录 `run_id` 与稳定 `rid/action_id`。
- Harness 原语是消息级 `append|replace|remove|fork|end|suspend|resume|cancel`，事件另有 `ready|start|finish|commit|join`，每个 action/call 用稳定 `turn_id,call_id,ordinal,version_id`；`replace/remove` 按原生消息 ID 在调用边界改变当前视图，不删原日志/工件。将版本记为 `(model_revision, template_tokenizer_hash, token_ids, position_layout_dtype_hash, prefix_history, isolation_domain)`；DSH 提供语义日志，SGLang 产实际 token IDs 作为权威。仅重用相同隔离域、模板、layout、位置与兼容操作历史下相同 token 前缀。append 继承历史；fork 只在真实继承的前缀上继承；replace/remove 从第一个不同 token 后创建历史边界，其后的旧 KV/线性状态不可拼到新前文；不同历史即使最终文本相同也不误命中。不能证明历史兼容时对目标使用新 radix namespace 并完整预填充，不伪称命中。工具结果不得作为可丢弃 KV。
- 每分支一个已提交指针、一个候选；logical `active/suspended/expired` 与 residency `hbm/host/absent` 分开，候选 `preparing/ready/canceled` 独立。基于稳定消息边界冻结；许可后对 frozen 内容生成/取固定摘要、以实际模板预填充；期间只允许追加在独立尾上。τ/token prefix 未变时由引擎用真实安全前缀补算尾；非 append 则作废候选。仅在下一调用提交边界、版本 CAS、完整尾 token 身份和引擎 READY 均通过后切换。旧请求和 child 保有租约，旧指针退休不释放它们的物理依赖；软窗口不足时走旧版，若 `prompt+max_new_tokens > 32768` 则同步压缩，仍超窗时报显式 context error，禁止悄悄截断。固定摘要 E3 保持摘要文本与切换位置一致，闭环 E3 由相同模型生成摘要并计时；同场景固定切换位置，提前返回时只丢候选准备，不在两组用不同可见文本。
- 引擎返回 `epoch,seq,action_id,status,version_id,matched_tokens,full_kv_slots,recurrent_slots,unique_hbm_bytes,unique_host_bytes,reserved_bytes,fg_queue,bg_queue,transfer_bytes,transfer_us,error`；后台准备/恢复按完成事件而不是 RPC 返回计 READY。通过唯一物理分配 ID 去重，HBM 与 DRAM 各自真实副本、尚未物化的 reservations 单列，不能把池的空槽视为已使用。解码、child、复制与恢复租约分别持有并只释放一次；scheduler 线程串行校验 + 排程，GPU stream 事件确认后才移除 inflight；回收条件是目标副本无活跃物理 lease 且 inflight=0。逻辑仍存活但无物理 lease 时可驱逐，保留完整 token 序列以合法重建。引擎掉线/epoch 变更清除物理句柄、取消许可，版本仍可从提交日志冷重建；尚未确认副作用不自动重试，重启中的活跃实验标失败。快照缺失或过期不启动后台，前台只做可容量核准的按需重算/恢复。

### 4. 接入 DSH 的确认调用、版本原语、并行、委派与结果缓存

### 6. 用同一动作执行器实现强组合和联合控制

- `policy.py` 读取确认节点、版本/租约、前后台队列、各池 free/owned/reserved 与完成反馈，发带版本及 expiry 的 `admit|defer|retain|offload|restore|recompute|prepare|pause|reclaim`。先 drain 回执、处理可回收过期副本与承诺前台的必要动作；前台合法 ready age ≥500 ms 按老化选可行候选，同分按 ready 时间、session、branch、action ID。尚未提交的非老化分支可与准备/放置竞争；只有已有 SGLang 前台排队时暂停发可选后台，不能把中间层待选 ready 当成引擎积压。每次只进 1 个可选后台动作；已发 CUDA copy 不取消，必要前台 restore 不受后台门控。事件驱动，25 ms tick 计 age/指标，资源快照 >100 ms 不准新后台。
- 针对第 1–4 周和留出前置 microbench 冻结 calibration：按前缀长度 `[1,1024,4096,8192,16384,32768]`、batch `[1,4,8]` 记录 5 次 warm-up + 20 次采样的 prefill、D2H/H2D、recurrent restore 快照，缺 bucket 使用同大小上邻桶而不外推；按等待类型（已知 local tool、delegation、trace barrier、approval）统计剩余等待 Kaplan–Meier/经验生存率，返回后只更新同类型 EWMA `α=.2` 的实际传输/队列成本，不用当前任务未来时间。按 `reload_ms = setup_ms + transfer_bytes / measured_bytes_per_ms + queue_ms`，选择便宜且可行的 restore 或 cold recompute；留驻的收益由当前匹配可避免的重算/重载时间与预计复用概率相乘。`eta=min(1, wait_remaining_p50_ms / action_cost_ms)`（零时长为 1）；后台需通过 `eta*stall_ms >= measured_transfer_ms + queue_ms + P_evict*restall_ms`，其中 `P_evict` 为同压力档校准样本在预测窗口内提前被回收/作废的经验比例。没有足够观测（<10）时后台不投机，强组合与联合使用相同保守门控。
- 联合按 `saved_fg_ms-added_fg_ms-λh*ΔGiB·s_h-λd*ΔGiB·s_d` 排剩余可行动作，已知 DAG 的剩余关键路径为最长路径（未知未来长度为 0，只使用已确认节点的服务估计）。每个池 `λ= max(0,occupancy-.60)/.40 × p50_recompute_ms`，以每 GiB·s 计；Δ 取实际独占增量和在途目标 reservation，前台分支也计其后续 decode 增量/恢复债务，候选旧新共存时间用同一预测窗口上限 2 s；负收益可选项不做，必要前台/释放不因分数为负被丢弃。每接纳一项更新池级 reservations、重算可行性；设备负载 ≥85% 禁止可选迁入，≤70% 才恢复该类迁入，非必要同一版本迁移冷却 500 ms；安全 invariant 否决优先。记录每个候选的选择/拒绝、各成本和动作实际耗时。
- `strong` 使用同一合法集合、前台 age、硬容量、恢复代价、准备 slack/滞回与预算：每个子策略分别选择本类最优（执行按合法 ready 剩余长度、放置按本版本 reload/recompute、准备按自身可隐藏成本）；同一 tick 固定优先级为必要前台 → 准入 → 恢复/放置 → 准备，硬门控无法预留便等待，不以其他模块的效用抢占。`joint` 只替换最后可选项的仲裁：在同一候选集合比较分支新增状态、准备与恢复债务。`simple` 为独立策略+硬门控但无 age 与 slack 保护，不当主对照。`parallel-only|lifecycle-only|offload-only|lookahead-only` 各只开命名机制，其他为串行、未预准备、原生驱逐或按需恢复；`ttl` 在可回收挂起副本上固定 200 ms 冷却后逐出；`task-prefix` 按 ready 最长路径、命中长度、老化选择前台，不开准备；`joint-no-prefetch` 保留按需 restore，禁后台迁入；`joint-no-predict` 全部非必需动作使用不依赖等待估计的门控（不预准备/预取、保留同硬约束），`oracle` 仅在同一回放知道真实剩余等待替换预测值，只作为可行 oracle 参考线，不声称数学上界。结果 cache 默认关闭来比较论文各机制；相同 `joint` 另做 `tool-cache=off/on`。

### 7. 场景特化只引入可以独立消融的优化

- 首选工具等待期间的兼容前缀提前恢复/候选准备、子分支引用去重（只持共享前缀一次）、page_size=1 的同形批描述符合并；收益分别报告 `strong/joint`、准备开/关、Triton kernel 开/关。不改模型权重、注意力公式、任务分解、输入内容或所需结果集合。调参只使用校准周与固定 fixture，不从留出周挑阈值；观察到无法压低 P95 时报告无增量，不能用 hit-rate、吞吐或仿真替代。
- E1 两个真实只读工具读同一快照故意倒序；E2 同工作量扫 `1,2,4,8` 并发、独立 IO 与 CPU 校验；都对照 serial/合法即发/预算派发。E3 扫等待 `25/250/2000` ms，提前返回在计划 25%，同边界分别测固定摘要和含真实摘要成本。E4 覆盖父子共享、D2H/H2D lease、父提前结束/取消；E5 同 tick `fork admit + candidate prepare + restore`，记录排序原因。E6 首基线实测 Full token、Mamba slot 上限的 `100/80/60%` 向下取整作为 `--max-total-tokens` / `--max-mamba-cache-size`，各臂用同上限；不足一条完整上下文或 8 个活动状态则同档全臂采用满足契约的最小值并披露实际比例。host `--hicache-size` 每档按 `(16,16,4)` GB，native-radix 明确无 L2。敏感性图单列 strong/joint 的同一 50% 实测带宽令牌桶限流（非物理降频），不拿它直接与不限流 native 横比。固定 E6 漂移每第四个屏障提前至 25%，另一组延至 2 倍；oracle 仅用于回放。
